## Spec
Feedback del usuario sobre el chat "Leadtita" de /lead-suite (captura: para "le mandé hola cómo andás a 395 Realty" devolvió una lista gigante de 7 leads, el usuario tuvo que elegir, y el bot respondió con `**negritas**` sin renderizar y el id interno "(id uq01tiv2c9wib1j)").
Objetivo:
1. **Tipografía y formato**: todo el panel con Geist Sans (la fuente de la app, sin fallbacks raros); las respuestas del bot se renderizan como Markdown seguro reutilizando `renderMarkdown` de lib/markdown.ts (negritas, listas, links), estilos acotados al chat.
2. **Conciso**: prompt del sistema que obliga respuestas cortas (1–3 oraciones), sin repetir lo que dijo el usuario, sin mostrar ids internos nunca, preguntando solo el dato que falta. Defaults inteligentes: si no dice canal pero el mensaje lo implica, inferirlo; si no dice fecha/hora → ahora; estado → contactado.
3. **Contexto de los leads**: antes de responder, el agente tiene contexto compacto de los leads del usuario (nombre, rubro, zona, estado de contacto, último contacto; los N más relevantes por coincidencia con el mensaje, no todos) para resolver a qué lead se refiere con búsqueda difusa (acentos, mayúsculas, nombre parcial). Si hay un único candidato claro, lo usa directamente; si hay ambigüedad, ofrece como máximo 3 opciones cortas (nunca una lista gigante).
4. **Puede modificar, no solo cargar**: herramientas para leer el historial de un lead, actualizar el estado del lead, editar o borrar un contacto registrado (mensaje, canal, fecha, estado, notas) y agregar notas. Agregá en lib/server/lead-suite.ts las funciones necesarias (p. ej. `updateLeadContact`, `deleteLeadContact`) con verificación de pertenencia y actualización consistente de `contact_status`/`last_contacted_at` del lead.
5. **Confirmación precisa Sí/No**: toda escritura (crear/editar/borrar/cambiar estado) NO se ejecuta directo: el bot responde con una acción propuesta y la UI muestra una tarjeta clara "Hacer cambios en **395 Realty LLC**: registrar contacto por WhatsApp, hoy 22:05, mensaje 'hola cómo andás'" con botones **Sí** / **No**. Sí → ejecuta y confirma en una línea; No → cancela y pregunta qué ajustar. Seguridad: la acción pendiente no puede ser alterada por el cliente: firmala (HMAC con un secreto del servidor existente en env) o guardala del lado servidor con id y expiración; al confirmar, re-validar pertenencia y argumentos.
6. Mantener: auth, límites de tamaño, máx iteraciones, timeouts, gratis (sin créditos), i18n es/en mismas claves, accesibilidad (botones Sí/No con foco), marca leadta.
Puede editar: solo los `archivos` listados. Cualquier otro archivo requiere `ask` (no edites dashboard.tsx, leads-list.tsx ni lead-suite.css: los edita otro worker; si necesitás que el dashboard refresque tras una acción confirmada, usá el `onActivity` existente).
Restricciones: AGENTS.md y CLAUDE.md del repo, sin commits, sin comandos de base, no tocar la terminal del dev server.
Hecho cuando: el flujo de la captura se resuelve en 1–2 turnos con tarjeta Sí/No, sin ids ni listas largas, Markdown renderizado, y se puede editar un contacto existente con confirmación.
Evidencia requerida: `npx tsc --noEmit` y `npx eslint lib/server/lead-suite-agent.ts lib/server/lead-suite.ts app/api/lead-suite/chat "app/[locale]/lead-suite/chat-panel.tsx"` exit 0; prueba real con la cuenta de prueba (te la paso por mensaje): (a) "le mandé hola cómo andás a 395 realty por whatsapp" → tarjeta Sí/No → Sí → registrado; (b) "cambiá el canal del último contacto de 395 Realty a email" → tarjeta → Sí → actualizado; (c) No → no cambia nada. Capturas en docs/qa-mobile/leadtita-*.png.
Cierre: `worker_done` con resumen de 6 líneas como máximo.
