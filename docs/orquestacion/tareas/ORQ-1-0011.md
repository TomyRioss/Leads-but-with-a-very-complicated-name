## Spec
Contexto verificado: en la PocketBase real NO existen las colecciones `subscriptions`, `subscription_payments` ni `subscription_checkout_locks` (GET devuelve 404; solo existen users, lead_batches, leads, credit_locks). Por eso `/owner` falla en métricas y usuarios, y también fallarían checkout y webhook de Mercado Pago. El usuario autorizó acceso total a la DB para esta tarea, pero el ORQ ejecuta el script; vos solo escribís código.

1. `scripts/apply-subscriptions-schema.mjs` (Node ESM, sin dependencias; copiá el patrón de `scripts/seed-owner.mjs`: parser de `.env.local`, auth superuser, header `X-Leadta-Bridge-Key` si existe, `--dry-run`, nunca imprime secretos). La relación `user` usa el id real de la colección `users` (consultalo por API); `subscription_payments.subscription` usa el id de la colección `subscriptions` recién creada.
