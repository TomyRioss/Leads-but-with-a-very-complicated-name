## Spec
Objetivo: el usuario quiere eliminar leads de una lista (lote) para dejarla limpia antes de exportar. Implementá la API:
`DELETE /api/leads` con body `{ batchId: string, leadIds: string[] }` (1 a 200 ids, validados) → `{ deleted: number }`.
- Auth obligatoria (`getCurrentUser`), 401 sin sesión. Verificar que el lote pertenece al usuario (`batch.user`) y que cada lead pertenece a ese lote; ids ajenos se ignoran o devuelven 403 (sin filtrar información).
- Borrado eficiente: sin N+1 serial (concurrencia acotada, p. ej. 5, o batch API de PocketBase si existe en la versión usada: revisá deploy/pocketbase y lib/server/pocketbase.ts). Errores parciales: devolver cuántos se borraron y cuáles fallaron.
- Importante: leadta tiene dedupe de "locales ya vistos no vuelven a aparecer". Revisá cómo se calcula (app/api/search/route.ts) y asegurate de que borrar un lead NO haga que vuelva a aparecer en búsquedas futuras ni rompa ese dedupe (si el dedupe se basa en los leads existentes, `ask` con una propuesta antes de borrar físicamente; alternativa: borrado lógico con un campo, que requeriría migración: proponela en el `ask`).
- No reembolsa créditos (el lead ya se entregó).
- Contadores del lote (si el batch guarda cantidad de leads): mantener consistentes.
- Lógica en `lib/server/leads.ts` (repositorio), route delgado. Errores con el patrón existente (lib/server/public-error.ts).
Contrato para la UI (ORQ-1-0100, la hace otro worker después): el método, body y respuesta de arriba, exactos.
Puede editar: solo los `archivos` listados. Cualquier otro archivo requiere `ask`.
Restricciones: AGENTS.md y CLAUDE.md del repo, sin commits, sin comandos de base ni migraciones (salvo que el usuario lo apruebe vía `ask`), no tocar la terminal del dev server. No edites app/api/search/route.ts ni lib/server/credits.ts.
Hecho cuando: el endpoint borra leads propios del lote de forma segura y el dedupe sigue funcionando.
Evidencia requerida (headless): `npx tsc --noEmit` y `npx eslint app/api/leads lib/server/leads.ts` exit 0; explicar cómo queda el dedupe.
Cierre: `worker_done` con resumen de 6 líneas como máximo.
