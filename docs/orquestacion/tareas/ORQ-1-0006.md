## Spec
Objetivo: el owner deja de tener login propio por variables de entorno. Es el usuario de PocketBase con `users.role = "owner"` (creado por ORQ-1-0005). Inicia sesión por el login normal y, al hacerlo, se lo redirige solo a `/owner`. Los endpoints `/api/owner/*` se protegen con ese rol.

Leé AGENTS.md y la guía de route handlers en `node_modules/next/dist/docs/`. Contexto: hoy `lib/server/owner.ts` firma una cookie propia `leadta_owner` con `OWNER_EMAIL/OWNER_PASSWORD/OWNER_SESSION_SECRET` y `app/owner/owner-panel.tsx` tiene su propio formulario. El campo `role` ya existe en la DB (select `user`|`owner`, vacío = usuario normal) o lo tendrá antes del deploy; el código debe funcionar aunque falte (trata cualquier cosa distinta de `"owner"` como usuario).

Cambios:
1. `lib/server/auth.ts`: `AppUser` suma `role: "user" | "owner"`; `getCurrentUser` lo mapea desde `auth.record.role` (solo el string exacto `"owner"` da owner).
2. `app/api/auth/login/route.ts`, `me` y `register`: devuelven `role` en `user`. Registro: nunca envía `role` a PocketBase.
3. `lib/server/owner.ts`: `requireOwner(request)` pasa a usar `getCurrentUser` (cookie `leadta_session`): sin sesión → 401, sesión sin rol owner → 403; devuelve `null` si OK. Eliminá la cookie HMAC, `verifyOwnerCredentials`, `setOwnerCookie/clearOwnerCookie`, el rate limit de login y todo uso de `OWNER_*`. Eliminá `app/api/owner/login` y `app/api/owner/logout`; `GET /api/owner/me` sigue existiendo y responde `{owner:true}` o 401/403. Todos los demás `/api/owner/*` siguen igual salvo cambiar la verificación.
4. `app/auth-form.tsx`: tras login (y registro) exitoso, si `user.role === "owner"` redirigir con `window.location.assign("/owner")`; si no, el comportamiento actual intacto. No toques `app/buscar/page.tsx` (lo edita otra tarea).
5. `app/owner/**`: sin sesión o sin rol owner → redirigir a `/buscar` (sin formulario de login propio; eliminá ese código y estilos muertos). `Salir` usa `POST /api/auth/logout` y vuelve a `/buscar`. Mantené todo lo demás del panel.
6. `.env.example`: quitá `OWNER_*`. `.env.local`: borrá solo `OWNER_SESSION_SECRET`; MANTENÉ `OWNER_EMAIL` y `OWNER_PASSWORD` (los usa el script de alta, que lee `.env.local`; nunca van versionados).
7. Seguridad: la contraseña del owner nunca aparece en el código; el panel no permite cambiar `role` de nadie (no agregues ese campo a ningún PATCH).

Puede editar: solo los `archivos` listados. Otro archivo requiere `ask`.
Restricciones: AGENTS.md y CLAUDE.md del repo; sin commits; REGLA DURA: no ejecutes nada contra la base de datos ni PocketBase (no levantes `npm run dev`); sin instalar dependencias.
Hecho cuando: ningún código lee `OWNER_*` ni `leadta_owner`; `/api/owner/*` exige rol owner; el login normal redirige al owner a `/owner`.
Evidencia requerida (headless): `npx tsc --noEmit` y `npm run lint` exit 0; `grep -rn "OWNER_\|leadta_owner" app lib` sin resultados. Un exit distinto de 0 en tus archivos = tarea fallida.
Cierre: `worker_done` con resumen de 5 líneas como máximo, archivos tocados y salida de la evidencia.
