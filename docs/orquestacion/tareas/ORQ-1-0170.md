## Spec
Pedido del usuario: trazabilidad de las conversaciones que los clientes tienen con Leadtita. Hoy viven solo en localStorage (lib/client/leadtita-history.ts). El usuario AUTORIZÓ crear esta colección nueva.

1. **Migración** (NO aplicarla; ORQ-1 la aplica): `pb_migrations/1794420000_add_leadtita_conversations.js`, mismo patrón que 1794410000_add_ai_usage.js / 1794390000. Colección `leadtita_conversations` (contrato fijo, ORQ-1-0171 lo lee):
   - `user` relation→users, required, maxSelect 1, cascadeDelete true
   - `client_id` text required max 64 (id local de la conversación)
   - `title` text max 200
   - `messages` json (maxSize 2_000_000) = array de mensajes tal cual StoredConversation.messages
   - `extra` json (maxSize 500_000) = StoredConversation.extra (estados de tarjetas: confirmada/rechazada, incluye borradores de mail)
   - `message_count` number, `last_message_at` date
   - autodate `created`, `updated`
   - índices: UNIQUE (user, client_id); (user, last_message_at)
   - reglas list/view/create/update/delete = null (solo superusuario; todo pasa por el server).
   - down: borra la colección.
2. **Servidor** `lib/server/leadtita-conversations.ts` (superusuario como el resto de lib/server): list(userId) (sin messages, ordenado last_message_at desc, máx 30), get(userId, clientId), upsert(userId, conv) validando tamaños (MAX_STORED_MESSAGES 200, title 200), delete(userId, clientId). Siempre filtrar por user del token, nunca por id del body.
3. **API** (auth obligatoria, solo el propio usuario): `GET/POST /api/leadtita/conversations` (listar / upsert), `GET/DELETE /api/leadtita/conversations/[id]`.
4. **Cliente** `leadtita-history.ts` + chat-panel.tsx: el servidor pasa a ser la fuente de verdad; localStorage queda como caché. Al cargar: traer lista del server; si el server está vacío y hay historial local → subirlo una vez (migración local→server). Guardado con debounce (~1.5s) tras cada mensaje/cambio de tarjeta y al ocultar la pestaña (`visibilitychange`/keepalive). Errores de red no rompen el chat (sigue en local, reintenta en el próximo guardado). Borrar conversación borra en server.
5. Eficiencia: no reenviar conversaciones sin cambios (hash/updatedAt), un solo request por guardado.
Puede editar: solo los archivos listados (pedí otros con ask).
