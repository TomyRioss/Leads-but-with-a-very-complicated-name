## Spec
Objetivo: los mensajes de error que ve el usuario dentro de la app (p. ej. el banner rojo de /buscar "Unexpected token '<', "<!DOCTYPE "... is not valid JSON" con botón "Cerrar"; también los de historial page.tsx:376 y Lead Suite dashboard.tsx:104 / chat-panel.tsx:168) deben incluir, en producción, un botón "Enviar reporte". Al hacer click abre el modal de Comentarios existente (`FeedbackDialog`, app/feedback-dialog.tsx, montado en app/app-sidebar.tsx) con todo precargado automáticamente: tipo/categoría de reporte de error si el formulario la tiene, y en el mensaje: texto del error, página/ruta, acción que se estaba haciendo (si se conoce), fecha/hora ISO, idioma, user agent y, si existe, status HTTP / id de request. El usuario puede editar antes de enviar.
Diseño técnico (mínimo y reutilizable):
- `app/error-report.ts` (cliente): `openErrorReport(context)` que despacha un `CustomEvent("leadta:open-feedback", { detail })` y un helper `buildErrorReport(...)` que arma el texto. Una sola fuente de verdad.
- `AppSidebar` escucha el evento y abre `FeedbackDialog` con props nuevas opcionales (`initialMessage`, `initialCategory` o equivalente según el form real). Sin prefill, el comportamiento actual no cambia.
- Si el form actual del feedback no admite precarga de categoría o necesita un campo de contexto, adaptá app/api/feedback/route.ts solo si hace falta (validación y límites de tamaño), sin romper lo existente.
- El botón aparece solo cuando `process.env.NODE_ENV === "production"` (en dev no). Va junto a "Cerrar" con estilo secundario, paleta AGENTS.md, ícono lucide-react opcional.
- No incluir datos sensibles (tokens, cookies, emails de terceros) en el reporte.
- Textos nuevos en messages/search/{es,en}.json.
Puede editar: solo los `archivos` listados. Cualquier otro archivo requiere `ask`.
Restricciones: AGENTS.md y CLAUDE.md del repo, sin commits, sin comandos de base, no tocar la terminal del dev server. No cambies el texto del error en sí ni arregles el origen del error JSON (eso es otra tarea).
Hecho cuando: en prod, cada banner de error mencionado muestra "Enviar reporte" y abre Comentarios con el reporte precargado; en dev no aparece.
Evidencia requerida (headless): `npx tsc --noEmit` y `npx eslint app/feedback-dialog.tsx app/app-sidebar.tsx app/error-report.ts "app/[locale]/buscar" "app/[locale]/historial" "app/[locale]/lead-suite" app/api/feedback` exit 0; pegar un ejemplo del texto precargado.
Cierre: `worker_done` con resumen de 6 líneas como máximo.
