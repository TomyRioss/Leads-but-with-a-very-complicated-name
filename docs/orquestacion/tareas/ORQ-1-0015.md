## Spec
Pedido del usuario: "que todo sea administrable, añadí un sidebar para tener todo más organizado y que haya una sección de auditoría con todo el historial y acciones visibles en la página". Tus secciones de Suscripciones/Pagos/Búsquedas ya existen (`app/owner/sections/*-section.tsx`, ORQ-1-0014); ahora armás el shell y las secciones restantes. W01 termina en paralelo el backend de acciones/auditoría (ORQ-1-0013): contratos abajo, leé sus handlers en `app/api/owner/**` a medida que existan para confirmar tipos.

### Shell con sidebar (`owner-panel.tsx`, `page.tsx`)
- Layout: sidebar a la izquierda en desktop (ancho fijo ~232px, sticky, alto completo) con el logo `BrandLogo` + badge Owner arriba, navegación y abajo el email del owner + "Salir". En móvil el sidebar pasa a una barra superior con botón de menú que abre el sidebar como panel deslizable (focus trap, Esc cierra, foco devuelto al botón), o a una barra inferior; decidí lo más usable.
- Secciones (orden): Resumen, Usuarios, Suscripciones, Pagos, Búsquedas, Auditoría. Iconos `lucide-react`. Sección activa en la URL (`/owner?s=usuarios`, valores: resumen|usuarios|suscripciones|pagos|busquedas|auditoria; default resumen) con `router.replace` sin recarga; `aria-current="page"` en el ítem activo, `<nav aria-label>`, `<main>` con `h1` por sección. Cada sección se monta solo cuando está activa (lazy: `next/dynamic` o import condicional) para no pedir datos de todas.
- Mantené lo existente: chequeo de sesión por rol (`/api/owner/me`: 401/403 → `/buscar`, error de red con Reintentar), logout con `POST /api/auth/logout`. Pasá `onUnauthorized` a cada sección. Refactorizá el archivo para usar las clases/utilidades de `app/owner/ui.ts` (podés agregar ahí lo que falte) y eliminá duplicados. Sin CSS propio: solo Tailwind v4 con los tokens ya usados (`bg-(--paper)`, `text-(color:--ink)`, etc.). Usá `w-[calc(...)]`/`max-w-*` (no `min()` sin calc: ya dio overflow horizontal).
