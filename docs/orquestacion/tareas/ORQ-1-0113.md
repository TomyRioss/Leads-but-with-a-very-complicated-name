## Spec

Objetivo:
1. `planner.ts`: `planPeopleSearch` con OpenRouter (mismo patrón, env y modelo económico que app/api/analysis/route.ts), JSON validado, timeout. Clasifica tipo de perfil, rol y zona; genera 3–6 `webQueries` efectivas para encontrar PERSONAS independientes que publican contacto (no empresas), `githubQuery` solo para técnicos, `instagramQueries` (hashtags/keywords por oficio y zona) y `facebookGroupQueries`. Filtro de segmentos sensibles → `SensitiveSegmentError { suggestion }`. Que funcione igual de bien para "personal de limpieza en Palermo", "vendedores de seguros en Córdoba", "dev React freelance", "contador independiente en Rosario", "electricista matriculado zona norte".
2. `sources/serper.ts`: `searchSerper` (POST https://google.serper.dev/search con `X-API-KEY: process.env.SERPER_API_KEY`, `gl`/`hl` según ubicación, `num` ≤10), concurrencia ≤3, AbortSignal + timeout, extrae del título/snippet nombre, rol, teléfono, email y links wa.me usando helpers de lib/server/contact-scrape.ts (`isValidEmail`, `normalizePhone`, `socialNetworkOf`), marca `isBusiness` heurístico (SRL, SA, "empresa", "S.A.", directorios). Nunca loguear la API key.
3. `sources/github.ts`: `searchGithub` (search/users por lenguaje/ubicación + perfil para email/blog/twitter públicos; `GITHUB_TOKEN` opcional; respetar rate limit; concurrencia ≤3).
4. `.env.example`: agregar `SERPER_API_KEY=` y `GITHUB_TOKEN=` vacíos (no tocar .env.local).
